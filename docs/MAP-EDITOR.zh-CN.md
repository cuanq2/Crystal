# 地图可视化编辑器回归检查

旧版 `Microsoft.VisualBasic.PowerPacks.Vs` 在释放地图区域时会访问 .NET 8 中已移除的 `System.Windows.Forms.ContextMenu`，导致 `TypeLoadException`。地图区域现在使用本项目的 `MapRegionCanvas` / `MapRegion` 绘制和处理鼠标操作，服务端不再引用 PowerPacks。旧运行目录中残留的同名 DLL 不会被新程序使用。

中文下的“不筛选”选项通过选中索引设置，避免把英文名称当作已经翻译的显示文字进行查找。关闭窗口时解除全局事件订阅、清理聚焦状态并释放地图位图；刷新记录保留编辑器未展示的调度字段，数量或延迟不合法时阻止关闭，避免静默丢弃记录。删除记录后，父窗口按记录对象恢复选择，避免旧列表索引越界。

在源码仓库根目录运行（输出目录必须不存在）：

```powershell
dotnet run --project Checks/MapEditorCheck -c Release -- artifacts/map-editor-check
```

可额外提供现有运行目录的 `Server` 路径，检查地图列表第一张地图：

```powershell
dotnet run --project Checks/MapEditorCheck -c Release -- artifacts/map-editor-real E:\workspaces-zq\mir2-runtime\Server
```

检查在独立输出目录创建配置和模拟地图，只复制内容数据库 `Server.MirDB` 与首张地图文件，不读取账号库、不启动服务、不修改提供的运行目录。覆盖中英文界面的刷新点页签切换、绘制、鼠标悬停、拖动、聚焦和缩放、区域删除/添加、关闭后再打开、经典地图读取、父窗口列表缩短及原始刷新调度字段保留。输出截图可用于检查区域显示。

2026-10-22 的本地验证包括 `BichonProvince`（文件 `0.map`、360 条刷新记录）。此前服务端界面截图检查会禁用加载/关闭回调，不能覆盖这类窗口生命周期问题；本检查实际执行地图窗口的加载与关闭。

## 大量刷新记录的显示性能

刷新点列表使用 `RegionEntryPanel` 按可视范围显示行。全部记录及未保存字段仍保留在内存中，地图上的区域显示也不受列表滚动影响；不会在首次切换时为所有行创建原生窗口。每行怪物下拉框先保留当前怪物，展开时使用 `BeginUpdate` / `AddRange` 一次填入完整列表。

同机、同一地图的隔离实测：仅延迟填入下拉框时首次切换约 4.5 秒；增加按可视范围显示后约 0.16～0.32 秒，后续切换约 18～35 毫秒。首次只创建 8/360 行原生控件，完整怪物下拉框 555 项展开准备约 40 毫秒。耗时随电脑性能和窗口大小变化；检查输出 `PERF` 记录便于复测。

回归还验证滚动到屏幕外记录、鼠标滚轮、筛选、完整下拉列表、原选项及未保存字段保留。优化集中在减少界面线程的重复工作，不从后台线程访问 WinForms 控件。
